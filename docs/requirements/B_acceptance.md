# B — 受け入れ条件 / Definition of Done: 顧客離脱予兆検知 兼 クロスセル推奨システム

> 出荷可能（予算ホルダー向けデモとして成立）と判断するための受け入れ条件。各条件は A 文書
> （[`A_requirements.md`](A_requirements.md)）と同一の `FR-x` / `NFR-x` アンカーで突合する。
> `FR-2x` 系は「出荷には必要だが元の要件定義書に明示が無い」項目で、`claim-audit place` の
> **gap（抜け）** として機械検出されることを意図する。

## 機能の受け入れ条件（A と一致すべきコア）
- **FR-1** LightGBM（既定）の二値分類で各顧客に 0〜100% の離脱確率が付与される。
- **FR-2** 顧客属性・利用ログ・支払履歴・サポート問い合わせ回数が特徴量として取り込まれる。
- **FR-3** 問い合わせテキストが埋め込み化され、「解約匂わせ」参照ケースとの類似度が算出される（既定は TF-IDF、任意で Sentence-Transformers）。
- **FR-4** テキスト類似度スコアが離脱モデルの特徴量に結合され、寄与が確認できる。
- **FR-5** 任意の高リスク顧客を選ぶと、SHAP 寄与度（上位要因）が可視化される。
- **FR-6** 各顧客に対し上位 3 件のクロスセル推奨が生成される。
- **FR-7** 推奨は協調フィルタ（item-item）と NetworkX グラフ指標で根拠付けされ、アクティブ顧客を主対象とする。
- **FR-8** 高リスク顧客がリスク％降順でソート表示される。
- **FR-9** Streamlit 一画面にアラートリスト・SHAP・クロスセルの 3 ブロックが表示される。
- **NFR-1** Python 3.10+ で動作する。
- **NFR-2** 同梱の合成データ（顧客テーブル＋購買履歴＋サポートテキスト 100 件以上）のみで外部接続なしに起動できる。
- **NFR-3** 離脱分類の AUC / Accuracy がホールドアウト評価で提示される。

## 出荷に必要だが元要件に明示が無い条件（gap 候補 = 抜け）
- **FR-20** 合成データは乱数シード固定で再現可能であり、生成スクリプトが同梱される。
- **FR-21** クラス不均衡（離脱少数）に対する取り扱い（クラス重み等）が施される。
- **FR-22** 推奨ロジックは、既に購入済みの製品を推奨から除外する。
